# study-bot — подготовка к ЕГЭ

Небольшой Flask-сайт и Telegram-бот на aiogram 3. Бот собирает ежедневную активность и результаты;
сайт хранит цели, расписание и настройки, показывает графики. Общая база SQLite и общие сервисы,
без Redis, очередей и SPA.

## Что работает

- Вход через Telegram, имя, пол и часовой пояс.
- Один учитель у ученика; несколько учеников у учителя. Совмещение ролей одним аккаунтом.
- Приглашение учителя с подтверждением ученика. Учитель редактирует план, но не результаты.
- Готовые предметы ЕГЭ-2027 и свои задания с максимальными баллами и шкалой перевода
- Пересекающиеся группы заданий: стандартные тестовая и вторая части, а также свои группы
- Отдельные страницы «Цели» и «Расписание» с карточками в центре
- Карточки с заливкой фона по прогрессу, до трёх в ряд, включая центрированный неполный ряд
- Круглые кнопки добавления и редактирования в правом нижнем углу
- Аватар Telegram рядом с именем при наличии фото в проверенных данных входа
- Выход из аккаунта в настройках
- Раздел «Редактирование»: работы, цели и расписание, предметы, группы, задания и шкалы перевода
- Недельные цели по созданным группам или нескольким выбранным номерам заданий
- Для группы подсчитываются решения заданий либо полные выполнения группы
- Повторение целей и слотов на 1–52 недели. Область изменения выбирается перед сохранением.
- Слоты с несколькими заданиями, пробники и дни отдыха. Слоты служат ориентиром.
- Ввод занятия в одном редактируемом сообщении: предмет, группа, решавшиеся задания, ошибки и баллы
- Все задания изначально выбраны, ошибки — нет; есть кнопки выделения и снятия всего списка
- После сохранения — вопрос о самочувствии с пятью эмодзи в том же сообщении
- Пробники: итоговый первичный балл, баллы списком или выбор решённых заданий кнопками
- Однобальные задания пробника отмечаются одним нажатием, для остальных уточняются баллы
- Пробники отдельно от обычных целей; первичные баллы суммируются, вторичные берутся из таблицы.
- История, исправление и удаление своих результатов на сайте; ввод за прошлую дату в боте.
- Ежедневный вечерний опрос, отключаемые напоминания за 15 минут, воскресные итоги.
- Необязательный опрос самочувствия один раз в день, без советов и интерпретации.
- Аналитика в карточках: календарь занятий, пробники по шкале 0–100 и динамика отдельных заданий
- Фильтры предмета, периода и типа работ; правильные, частичные решения и пропуски считаются отдельно
- Исправление результатов на сайте с сохранением исторических максимумов и шкалы; балл пробника можно внести вручную
- Экспорт своих данных в JSON и удаление аккаунта в настройках
- Удаление неиспользуемых предметов, заданий и своих групп с защитой истории
- История по 50 записей, серверные периоды аналитики до года

## Команды бота

`/practice` — записать занятие, `/exam` — пробник, `/goals` — цели недели,
`/weekly` — итоги недели; история и исправление записей доступны только на сайте
`/rest` отключает сегодняшнее вечернее сообщение, сохраняя занятия; дни без записанных занятий считаются отдыхом
`/cancel` отменяет текущий ввод,
`/help` выводит справку, `/start` — приветствие без кнопок

## Формулировки бота

Все сообщения и подписи кнопок находятся в [`study/bot_messages.toml`](study/bot_messages.toml)
Там же — ошибки ввода, напоминания, опросы и недельные отчёты

Меняйте текст справа от `=`, сохраняя названия разделов, ключи и подстановки в фигурных скобках
Например:

```toml
[entry]
subject = "По какому предмету запишем результат?"
task_score = "{task_name}: сколько баллов из {maximum}?"
```

`\n` задаёт перенос строки, списки содержат варианты сообщений или подписи оценок
Имена, названия предметов, групп и заданий берутся из базы и редактируются на сайте

В Docker файл подключён напрямую, обычные изменения подхватываются без пересборки образа
Если редактор сохраняет файл через замену, переподключите его командой
`docker compose up -d --force-recreate web bot` — изменения точно попадут в оба контейнера

## Production

Для публичного запуска используйте [инструкцию безопасного развёртывания](docs/production.md),
`.env.production.example` и оба файла Compose: `compose.yaml` + `compose.prod.yaml`.
Инструкция включает HTTPS, миграции, резервное копирование, восстановление и откат.
Обычная конфигурация ниже предназначена для локальной разработки.

## Локальный запуск в Docker

1. Создайте бота через [BotFather](https://t.me/BotFather), получите токен и username.
2. Скопируйте `.env.example` в `.env`. Укажите `BOT_TOKEN`, `BOT_USERNAME` без `@`, `BASE_URL`.
3. Создайте `SECRET_KEY`: `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`.
4. Для рабочего сервера укажите HTTPS-адрес и `COOKIE_SECURE=true`.
5. В BotFather выполните `/setdomain` для домена сайта — это нужно Telegram Login Widget.
6. Выполните `docker compose up --build -d`.

Сайт слушает `127.0.0.1:8000`. Для внешнего доступа направьте HTTPS reverse proxy на этот порт.
Адрес и порт публикации задаются в `.env`: `WEB_BIND_ADDRESS=127.0.0.1`, `WEB_PORT=8000`.
Данные находятся в именованном томе `study-data`. Не удаляйте его при перезапуске.
Бот стартует после проверки готовности сайта. Запускайте только **один экземпляр бота**.

Откройте бота и нажмите `/start`, затем войдите на сайт
В аккаунте без предметов появятся русский язык и профильная математика ЕГЭ-2027
Остальные готовые предметы выбираются в настройках, собственные предметы и задания тоже доступны
Каталог основан на проектах ФИПИ для 2026/27 учебного года, источники и статус шкал описаны в [docs/exam-catalog.md](docs/exam-catalog.md)
Подтверждённая шкала перевода ЕГЭ-2027 пока не заполнена — до её ввода сохраняются первичные баллы
Светлая и тёмная темы переключаются в шапке, выбор сохраняется в браузере
Для новых аккаунтов доступ учителя к самочувствию включён по умолчанию, существующие настройки сохраняются
Ученик сам управляет доступом к самочувствию и может отключить учителя.

## Локальная разработка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
cp .env.example .env
# Заполните .env, включая SECRET_KEY.
.venv/bin/flask --app study.wsgi run --port 8000
# В другом терминале:
.venv/bin/python -m study.bot
```

Для настоящего Telegram-входа нужен настроенный домен. Для локальной разработки задайте
`DEBUG=true` в `.env` и перезапустите сайт: на странице входа появится кнопка «Войти как первый пользователь»
Она использует существующего пользователя с наименьшим ID. При `DEBUG=false` кнопка скрыта и маршрут недоступен
Тесты используют Flask test client без сети.

```bash
.venv/bin/python -m pytest -q
```

## Правила учёта

Выполнение задания считается попыткой, в том числе с нулём баллов. Пропущенное задание пробника
даёт ноль баллов, но не считается попыткой. Полная тестовая часть считается одним вариантом;
частично решённая часть учитывается по заданиям, но не как полный вариант. Пробники не увеличивают
обычные цели. Указание отдыха не удаляет ранее внесённые занятия этого дня.

Максимум баллов и шкала пробника сохраняются на момент записи. Изменение настроек не меняет
историю. При исправлении пробника используются его исходные максимумы и шкала.
Если строки перевода нет, вторичный балл не вычисляется. Интерполяции нет.

Цели и расписание повторяются в заданном конечном диапазоне. Слоты можно переносить;
для серии перенос сдвигает соответствующие даты на одинаковое число дней. Удаление в интерфейсе
удаляет только выбранную запись. Незавершённый ввод бота хранится в SQLite; `/cancel` его отменяет.
История доступна на сайте по 50 записей на страницу с фильтром предмета; полный экспорт — в настройках.

## Эксплуатация

Логи идут в stdout: `docker compose logs -f`. Учебные ответы и самочувствие в логи не записываются.
SQLite использует WAL, внешние ключи и ожидание блокировки. Для резервной копии используйте
SQLite backup API либо остановите оба сервиса перед копированием всех файлов базы.

В разработке схема инициализируется при запуске. В production сначала выполните
`python -m study.manage migrate` при остановленных web и bot, после резервной копии.
Сервисы проверяют версию схемы; неизвестные версии и несовместимые столбцы не исправляются автоматически.

Успешные уведомления сохраняются по уникальному ключу, поэтому обычный перезапуск не повторяет
сообщения. При аварии между приёмом сообщения Telegram и фиксацией в SQLite одно сообщение
может повториться. Неотправленный вечерний опрос догоняется в пределах текущего дня; старые дни
не рассылаются. Недельный итог отражает записи на момент отправки; обновлённый итог доступен по команде `/weekly`.

Зависимости для воспроизводимого запуска закреплены в `requirements.lock`; диапазоны прямых зависимостей — в `requirements.txt`.

Бот работает только в личных сообщениях. Без реального домена и `BOT_TOKEN` нельзя проверить Telegram-вход и доставку. `/health` проверяет web и чтение базы, `/live` — процесс.
Ответы бота сохраняются вместе с результатом и доставляются после commit с повторными попытками.
Проверка состояния бота: `python -m study.manage bot-health`.

## Структура

- `study/models.py`, `db.py` — небольшая схема и SQLite.
- `study/services.py` — правила учёта, доступы и аналитика.
- `study/web.py`, `templates/`, `static/` — сайт без фронтенд-сборки; графики на SVG.
- `study/bot.py` — сценарии с кнопками, сохранённые черновики и периодическая отправка.
- `tests/` — бизнес-правила, права доступа, Telegram-подпись и сценарии бота.

Telegram-вход реализован по [официальному описанию проверки подписи](https://core.telegram.org/widgets/login/).

Роль учителя выдаётся администратором и по умолчанию отключена. После обновления
остановите web и bot, сделайте резервную копию и выполните миграцию:

```sh
python -m study.manage migrate
python -m study.manage set-teacher 123456789
# Отозвать роль (аргумент — Telegram ID):
python -m study.manage set-teacher 123456789 --revoke
```

Учителю доступны приглашения учеников в настройках. Обычные пользователи не
могут создавать приглашения или получать доступ к планам учеников.
