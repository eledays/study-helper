# Результат подготовки к production — 15 октября 2026

Репозиторий подготовлен к развёртыванию на одном Linux-сервере по [production.md](production.md). Реальный сервер, домен и Telegram не переключались. Секреты `.env` и данные действующих пользователей не изменялись.

## Закрытие исходного аудита

| Проблема | Изменение |
|---|---|
| Небезопасная локальная конфигурация | Отдельный production-профиль принудительно отключает debug-вход, включает Secure cookies; настройки отказываются принимать HTTP BASE_URL, слабый/пустой ключ и отсутствующие параметры бота |
| Откат результата при сетевом сбое | Учебная запись и исходящий ответ фиксируются вместе; постоянная очередь отправляется после commit с повторными попытками |
| SQLite-транзакции во время Telegram await | Обработчики сохраняют отложенные запросы; сетевой вызов выполняется после завершения транзакции |
| Слишком длинные цели | Полоса фиксированной длины; сообщения разбиваются с сохранением HTML-тегов и учётом UTF-16 |
| Ложный health | Проверка базы с 503, отдельный /live, проверка scheduler/polling/очереди бота |
| Повторный вопрос самочувствия | Основной путь сохранения проверяет флаг уже заданного вопроса |
| Необработанные ошибки входных данных | Исправлено сравнение CSRF, добавлены границы дат и обработка переполнения; отказ базы возвращает 503 |
| Неограниченная история и аналитика | История по 50 записей с серверным фильтром; аналитика получает выбранный период; недельный отчёт не строит полную аналитику |

Дополнительно: экспорт собственного аккаунта, подтверждаемое удаление аккаунта и безопасное удаление неиспользуемых предметов/заданий/групп; защита от повторного создания стартовых предметов после их удаления; индексы; контроль версии схемы и отдельная миграция; проверенные SQLite backup/restore; изоляция контейнеров и пример HTTPS proxy; CI и рабочие инструкции мониторинга/обновления/отката. Значения секретов и SQL-параметров скрыты в диагностических исключениях. Блокировка бота пользователем отключает рассылку ему без глобального сбоя health.

- Дополнительные тесты проверяют: сохранность результата при сетевой ошибке, отсутствие отправки успеха при сбое commit, доступность независимой записи SQLite во время сетевого запроса, отсутствие двойной отправки при конкурентном запуске очереди, 30 сохранений при параллельных чтениях, пагинацию и серверный период, изоляцию экспорта/удаления аккаунта, защиту истории, WAL backup/restore и отказ от неизвестной версии схемы.

- Синтаксис JS и shell-скриптов, Compose production-конфигурация и `git diff --check` проверены.

## Границы готовности

Перед публикацией оператор выполняет внешний чек-лист из production.md: реальный Telegram Login с HTTPS-доменом, доставку уведомлений в нужном часовом поясе, доступ учителя, внешние резервные копии и оповещения. Локальные тесты не определяют максимальную ёмкость production-сервера: при увеличении аудитории нужна проверка задержек на целевом железе и объёме истории. Python-образ и зависимости нужно регулярно обновлять и перепроверять.

Система не обещает exactly-once доставку Telegram: авария после принятия сообщения Telegram, но до фиксации доставки в SQLite может привести к повторному сообщению. Учебные результаты защищены request_key и сохраняются независимо от доставки подтверждения.
